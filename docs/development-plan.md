# 独立 Seller ID 采集项目开发计划与交付记录

## 目标和范围

在当前目录建立 `uk_amazon_seller_asin` 独立项目，复制原店铺 ASIN 流水线的店铺分页、重试、完整性检查、代理协调、SellerSprite 两轮补全、详情补全和运行账本能力。新项目拥有独立 Git、依赖锁文件、配置、SQLite、事件日志、缓存和 Excel 输出；共享的只有外部代理控制器和 SellerSprite 服务。

## 输入合同

从 `卖家数据` 工作表第 2 行起读取 B 列。超链接目标优先解析 `me`/`seller` 参数，兼容纯 Seller ID 和 Amazon UK 卖家链接；名称来自超链接显示文本，纯 ID 以 ID 作为名称。完全空行跳过；只要行内还有内容而 B 列不能解析，就在创建 run 或发起网络请求前按行号终止。按首次出现顺序去重，保存源文件 SHA-256、行号、名称、原始链接、Seller ID 快照和去重统计。

## 业务改动

| 环节 | 原 v14 | 独立项目 |
|---|---|---|
| 初筛 | 评分和评论必须有值；评分至少 3.5，评论至多 300 | 两字段分别允许 NA；有值时仍检查原门槛；价格 £6.99–£50.00 |
| 历史库 | 普通卖家入口排除历史 ASIN | 固定关闭；历史阶段记录 skipped，不建立 MySQL 连接 |
| 配送/变体 | FBA、变体数不超过 3 | 保留；变体缺失淘汰 |
| 上架时间 | 0–720 天 | 0–180 天，含 180 天；日期缺失、无效、未来或超范围淘汰 |
| 子体销量 | 三个年龄段分别要求 100/200/300 | 删除筛选，字段仍保存 |
| 七天销量 | 仅 0–30 天且子体销量为空时查询 | 所有通过前面条件的产品都查询；固定日门槛 3，精确 `yes` 保留、`No` 淘汰 |
| 导出 | 5 张表 | `0-30天`、`31-180天`、`产品数据` 三张表，保留 19 列 |

## 实现边界

- `source.format` 固定 `seller_ids_b`；启动校验拒绝旧输入格式和 `historyFilter.enabled=true`。
- SQLite schema 固定 v15。run 元数据保存项目 ID、业务合同版本、配置哈希、源哈希、冻结 UTC 日期和创建时 Git 提交；合同哈希不包含 Git 提交，因此文档提交不阻断续跑。
- 配置模板为 `config/*.example.yaml`，本机配置为被忽略的 `config/*.local.yaml`。正式 `source.limit=0`，canary 配置独立为 1。输出根目录强制位于独立项目根目录。
- 共享代理控制器路径作为配置项传入，项目不复制控制器代码。源 Excel 只读；运行产物、缓存、日志、凭据和会话不进入 Git。

## 验证与验收

自动测试使用临时 Excel、SQLite 和模拟 MCP，覆盖输入异常、NA 组合、价格边界、0/30/31/179/180/181 天、未来/缺失日期、FBA、变体、子体销量任意值均进入七天任务、`yes`/`No`、协议暂停和续跑不重复、历史旁路、19 列三表导出。类型检查及 22 个测试文件共 117 项应通过。

真实验证只使用 canary 配置：先 1 个卖家，必要时最多 3 个；不得自动启动 11,459 家全量任务。记录 run ID、阶段状态、SellerSprite/代理可用性、7 天任务数量和导出结果。若没有合格候选，明确标记七天销量或详情链路未覆盖。
